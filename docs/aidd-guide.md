# AI駆動開発 (AIDD) 実践ガイド (AIDD Practice Guide)

本プロジェクトにおける AI駆動開発（AIDD: AI-Driven Development / Spec-Driven Development）の標準運用手順書です。

---

## 1. AIDD 開発サイクル（7ステップ）

開発は「思いつきでコードを書く」のではなく、仕様書（Spec）を軸に品質ゲートを通しながら進めます。

```
1. 【要望受付】 Issue/ユーザー依頼から要件を抽出
        │
2. 【Specify】 docs/specs/ に要件・受入条件（Given-When-Then）を言語化
        │
3. 【Plan / ADR】 docs/adr/ にアーキテクチャ方針を記録
        │
4. 【Tasks】 実装ステップをタスクリストへ分解
        │
5. 【Implement】 コード実装（差分最小化の原則）
        │
6. 【Verify】 scripts/verify_aidd_gate.ps1 実行 ＆ マルチデバイス実機確認
        │
7. 【Review / Deploy】 人間によるPR承認 ＆ deploy.ps1 による安全デプロイ
```

---

## 2. 品質ゲートの実行

コミットおよびデプロイ前には、必ず品質ゲートスクリプトを実行して検証します。

```powershell
./scripts/verify_aidd_gate.ps1
```

### 検証項目:
1. **機密ファイル漏洩検知**: `.env`, `.env.deploy` 等の認証情報ファイルが誤って Git ステージングされていないかを遮断。
2. **PHP構文チェック**: PHP CLI 環境が存在する場合、全 PHP ファイルに対して構文エラー（`php -l`）を自動スキャン。
3. **AIDD必須ドキュメント整合性**: 憲法（GEMINI.md）、仕様書、アーキテクチャ設計書等の必須ファイルが存在するか確認。

---

## 3. 人間とAIの役割分担 (Human in the Loop)

| 工程 | AIエージェントの役割 | 人間（開発者/PM）の役割 |
| :--- | :--- | :--- |
| **要件・仕様** | テンプレートに基づくドラフト作成、曖昧さの指摘 | 意図の決定、受入条件（AC）の最終承認 |
| **設計・計画** | ADR起票、タスク分解、影響範囲の調査 | アーキテクチャの妥当性判断 |
| **実装** | コード生成、差分最小化、エラー修復 | レビュー（PR差分の確認） |
| **検証・QA** | 品質ゲートスクリプト実行、静的検証 | 実機（PC/SP）での最終ビジュアル受入確認 |
| **コミット・デプロイ** | コミットメッセージ作成、デプロイスクリプト実行 | コミット・プッシュ・リリースの最終実行許可 |
