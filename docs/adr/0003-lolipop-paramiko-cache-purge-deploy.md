# 0003. ロリポップ共有サーバーにおける SSH+Paramiko 自動デプロイ及びキャッシュパージ方式の採用

- **ステータス**: 承認 (Accepted)
- **決定日**: 2026-09-09
- **決定者**: OSCSS 開発チーム

## 1. コンテキストと問題提起 (Context)
ロリポップ（LOLIPOP）共有サーバー上の WordPress テーマ環境（`bizjapan.oscarchair.jp`）へ変更を反映する際、FTPでの手動転送では反映漏れ、転送遅延、および LiteSpeed/OPcache のキャッシュ残留による不具合が頻発する課題があった。
安全かつ高速に最新コミットをサーバーへ反映し、キャッシュを一括消去する自動デプロイ手法の確立が求められた。

## 2. 検討した選択肢 (Considered Options)
- **選択肢 1: PowerShell + Python Paramiko による SSH リモート Git Pull ＆ PHPキャッシュパージ（採用）**
  - メリット:
    - 外部CIサービス（GitHub Actions）のシークレット設定やIP制限に左右されず、ローカル開発環境から直接ワンクリックで実行可能。
    - `git reset --hard origin/main` により、リモートの作業ツリーを確実にクリーンな最新状態に同期できる。
    - SSH セッション内でサーバー側 PHP CLI を叩き、`opcache_reset()` および `LiteSpeed\Purge::purge_all()` を即時発火可能。
    - 他の OSCSS プロジェクト（`oscss-wp-theme` 等）と完全に統一された運用が可能。
  - デメリット:
    - ローカル環境に Python および `paramiko` パッケージが必要。
- **選択肢 2: GitHub Actions による CI/CD デプロイ**
  - メリット: Push時に完全自動で発火する。
  - デメリット: ロリポップのSSHパスワードをGitHub Secretsに預ける必要があり、SSH接続のタイムアウトやIP制限でのトラブルシュートが複雑。
- **選択肢 3: 従来の FTP / SFTP クライアントによる手動アップロード**
  - メリット: 特殊なツールが不要。
  - デメリット: 手動ミス、キャッシュクリア漏れが防げず、AIDD運用に不適。

## 3. 意思決定 (Decision)
**選択肢 1** を採用。
`deploy.ps1` と `.env.deploy` を導入し、事前の AIDD 品質ゲート（機密漏洩・構文チェック）を通過した場合のみ SSH 接続を行い、リモート同期とキャッシュパージを一気通貫で実行する設計とした。

## 4. 結果と影響 (Consequences)
- **ポジティブな影響**:
  - デプロイ所要時間が手動FTPの数分から約5〜10秒へ大幅短縮。
  - キャッシュクリア漏れによる「変更が反映されない」トラブルの完全撲滅。
  - 機密保護ゲートにより、本番パスワードや環境変数ファイルの誤コミット・漏洩を未然に防止。
- **ネガティブな影響 / リスク**:
  - 初回セットアップ時にローカルPython環境の確認が必要。
