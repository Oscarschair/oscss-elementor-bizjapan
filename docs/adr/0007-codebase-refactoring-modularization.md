# 0007. コードベースのリファクタリング（モジュール分離・アセット一元管理・スクリプト最適化）

- **ステータス**: 承認 (Accepted)
- **決定日**: 2026-09-09
- **決定者**: OSCSS 開発チーム

## 1. コンテキストと問題提起 (Context)
機能追加（SEO、zh-HKローカライズ、自社フォーム、完全レスポンシブ）に伴い、以下の技術的負債および改善点が顕在化していた：
1. **アセットエンキューの分散**: 各モジュール（`bizjapan-seo-zhhk.php`、`bizjapan-contact-form.php`、`functions.php`）で個別に `wp_enqueue_style` / `wp_enqueue_script` が呼ばれており、依存関係やバージョン管理が煩雑になっていた。
2. **スクリプトの脆弱性とパフォーマンス課題**: `main.js` において、特定要素が存在しないページで `TypeError` が発生する潜在リスク（nullチェック欠如）、および `scroll` イベントの毎フレーム発火によるパフォーマンス低下（ジャンク）が存在していた。
3. **名前空間汚染**: `functions.php` 内でプレフィックスのない `add_enqueue_scripts()` 関数が定義されていた。

## 2. 検討した選択肢 (Considered Options)
- **選択肢 1: アセット管理の一元化モジュール化 & main.js の堅牢化（採用）**
  - `includes/bizjapan-assets.php` を新設し、全CSS/JSのエンキューとバージョン定数（`BIZJAPAN_ASSETS_VERSION`）を一元管理。
  - 各機能モジュール（SEO・フォーム）は純粋なビジネスロジックに特化（単一責任の原則）。
  - `main.js` に `requestAnimationFrame` によるスロットリングと null 安全ガードを導入し、JavaScriptクラッシュを完全防止。
- **選択肢 2: 現状維持のまま修正を行わない**
  - デメリット: 将来の機能追加時やキャッシュ更新時に反映漏れやスクリプトエラーが発生するリスクが残る。

## 3. 意思決定 (Decision)
**選択肢 1** を採用し、コードベース全体のリファクタリングを実施。

## 4. 結果と影響 (Consequences)
- **ポジティブな影響**:
  - `BIZJAPAN_ASSETS_VERSION` によるアセットの一括キャッシュバスター管理が実現。
  - `main.js` の軽量化・null安全性向上により、全ページでJSエラーゼロを達成。
  - モジュールごとの関心の分離（Separation of Concerns）により、保守性が飛躍的に向上。
- **ネガティブな影響 / リスク**:
  - 特になし。後方互換性を保ちながらクリーンな構成を確立。
