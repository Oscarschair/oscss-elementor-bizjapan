# 0001. Hello Elementor ベースのテーマ構造採用と初期構成の決定

- **ステータス**: 承認 (Accepted)
- **決定日**: 2026-09-09
- **決定者**: OSCSS 開発チーム

## 1. コンテキストと問題提起 (Context)
BizJapan 向け Web サイト構築において、デザインの柔軟性と運用更新性の両立が求められており、Elementor ページビルダーとの親和性が最も高いテーマ構成を選択する必要があった。汎用テーマでは不要なアセットやスクリプトが多く読み込まれ、パフォーマンス劣化やCSS競合が発生しやすい。

## 2. 検討した選択肢 (Considered Options)
- **選択肢 1: Hello Elementor をベースとした軽量テーマ構造（採用）**
  - メリット: Elementor公式推奨であり、極めて軽量（CSS/JSが最小限）。Theme Builderとの干渉がゼロ。
  - デメリット: テーマ側でリッチな標準デザインを持たないため、Elementor側でのスタイリングが必要。
- **選択肢 2: 一般的なフルカスタムテーマ**
  - メリット: 自由度が高い。
  - デメリット: Elementor との機能重複やCSSスタイルの衝突リスク、保守コストが増大。
- **選択肢 3: Astra や GeneratePress 等の既存多機能テーマ**
  - メリット: 多彩なカスタマイザー機能。
  - デメリット: Elementor でデザインを完結させる場合に不要なコードが多く残る。

## 3. 意思決定 (Decision)
**選択肢 1: Hello Elementor をベースとした軽量テーマ構造** を採用する。
サイト制作・デザインの主軸を Elementor に委ね、テーマは高速・軽量な土台に徹することで、Core Web Vitals の最適化とメンテナンス性の向上を図る。

## 4. 結果と影響 (Consequences)
- **ポジティブな影響**:
  - 不要なCSS/JSの排除による高いパフォーマンスの維持。
  - Elementor のアップデートに追従しやすく、破壊的変更のリスクを極小化。
  - プロジェクト憲章および標準ドキュメント構造（docs/, .gemini/）の導入により、AIエージェントと開発者の双方向メンテナンス性を確保。
- **ネガティブな影響 / リスク**:
  - テーマ側ではなく Elementor 側での設定・テンプレート管理が主体となるため、運用者側のElementorスキルが求められる。
