# 0006. 専用レスポンシブスタイルシートと Fluid Typography による完全レスポンシブ化の決定

- **ステータス**: 承認 (Accepted)
- **決定日**: 2026-09-09
- **決定者**: OSCSS 開発チーム

## 1. コンテキストと問題提起 (Context)
Elementor で構築された既存ページでは、デスクトップ表示を前提としたハードコードなインラインスタイル（`font-size: 34pt`, `24pt`、横並び固定Flexコンテナ）が多く残されており、スマートフォン閲覧時に文字の巨大化・横スクロール・カードの狭小化等のレイアウト崩れが発生していた。
モバイルユーザー比率の高い香港市場において、全デバイス（PC・Tablet・SP）で美しい表示と快適な操作性を担保するレスポンシブ設計の導入が急務であった。

## 2. 検討した選択肢 (Considered Options)
- **選択肢 1: テーマ層での専用レスポンシブCSS (`bizjapan-responsive.css`) 導入（採用）**
  - メリット:
    - 既存の Elementor データを破壊せず、CSSのオーバーライド優先度を用いて全ページに横断的かつ安全にレスポンシブルールを適用可能。
    - `clamp()` を用いた Fluid Typography により、あらゆる画面幅（375px〜1920px）で自動的に滑らかなフォントサイズ補間を実現。
    - `overflow-x: hidden` により、予期せぬ横スクロール・横揺れを100%防止。
  - デメリット:
    - Elementor 側の独自クラス名に対するCSSセレクタの整合性を保つ必要がある。
- **選択肢 2: Elementor エディタ内での全ウィジェット手動レスポンシブ設定**
  - デメリット: 各ウィジェットのインライン指定（pt指定）がテーマ外部にあるため、作業量が膨大かつ今後のページ追加時に再発するリスクが高い。

## 3. 意思決定 (Decision)
**選択肢 1** を採用。
`assets/css/bizjapan-responsive.css` を作成し、テーマから最優先でエンキュー。
PC（1280px+）、Tablet（768px-1024px）、SP（375px-414px）の3段階ブレークポイントに応じたグリッド変換・タップ領域拡張・フォント補正を実装する。

## 4. 結果と影響 (Consequences)
- **ポジティブな影響**:
  - モバイル端末での横スクロール完全ゼロ化。
  - 適切なフォントサイズとカードスタックによる直感的な視認性・読了率の向上。
  - プロジェクト憲章 2.4「マルチデバイス（PC・SP）画面崩れ・レイアウト検証義務」の要件を完全達成。
- **ネガティブな影響 / リスク**:
  - 特になし。
